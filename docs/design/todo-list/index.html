Agent todo list — candidates

1 · Mid-run, in the transcript

The list arrives between tool rows while the turn is still working. The rows above and below are the app's real .tool-call-row-button markup, so the candidates are judged against the register they actually have to live in: no fill, no icon column, --text-sm on --muted, verb one token brighter than target. The active row carries the app's one running mark (WorkingNest) rather than a second spinner invented for this surface.

2 · Settled, after the turn ends

Every item done, nothing running. This is the state the list spends most of its life in — scrolled past, read once. It has to get quiet without disappearing.

3 · First write

The agent has just published the plan and started nothing. There is no progress to report and no current step to name, so anything built around "3 of 6" or "now: …" has to hold up empty.

4 · In a full turn

One candidate at the chat measure, with the prompt above it and real work below, so the question is whether it reads as part of the conversation or as furniture dropped into it. ?frame=a|b|c|d renders this section alone.

5 · The other placement: pinned above the composer

Not a fifth candidate — a different answer to the same problem. The list is state, not an event, so it could live outside the scrollback entirely, the way QuestionDock takes the composer's slot. A turn that keeps working never scrolls it away. The cost: it competes with the composer for the one place the eye rests, and it has no history — scroll back a week and the plan is gone.

6 · Lifecycle

The same list at three moments, in the recommended behaviour: expanded on first write (you want to read the plan), expanded while working with finished items dimmed, then collapsed to one line once the turn ends. One card that updates in place — never one card per TaskUpdate, or a six-step plan leaves fourteen cards in the scrollback.

7 · Edge states

A cancelled item (Cursor's TODO_STATUS_CANCELLED), an item Grok referenced by id before ever sending its text, and a twelve-item list — the case where an always-expanded list becomes a wall.
